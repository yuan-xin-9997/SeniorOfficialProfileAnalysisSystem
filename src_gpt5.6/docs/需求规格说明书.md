# 高级官员履历分析系统需求规格说明书

版本：2.0（`src_gpt5.6`）
更新日期：2026-08-30

## 1. 项目目标

系统面向公开人物研究场景，将分散的高级官员公开履历转化为可检索、可追溯、可分析的结构化档案，并提供人物关系、信息采集、智能分析、任务审计和权限隔离能力。

## 2. 用户与权限

- 管理员：默认访问全部页面，维护用户页面权限。
- 普通用户：仅访问管理员授权页面。
- 用户名、密码、角色由 `data/password.txt` 维护，登录时自动同步到 SQLite。
- 未认证请求返回 401，无页面权限返回 403；敏感配置在界面和接口中脱敏。

## 3. 功能需求

### 3.1 登录

用户输入用户名和密码获取访问令牌；令牌过期或无效时回到登录页。登录页须展示系统定位和默认账号安全提示。

### 3.2 概览

展示履历总数、在任人数、覆盖机构数、任职经历数、人物关系数、最近更新履历和数据完整度提示。

### 3.3 履历档案

- 支持按姓名、现任职务、机构模糊检索，按状态与党内职务筛选。
- 党内职务筛选维度包括中央政治局常委、中央政治局委员、中央委员、中央候补委员，采用层级语义（政治局委员亦是中央委员，常委亦是政治局委员），并可与状态筛选叠加。
- 档案列表支持分页浏览，筛选或重新查询时从第一页开始。
- 支持新建、查看、编辑和删除。
- 基础字段包括姓名、性别、出生日期、民族、籍贯、学历、现任职务、机构、行政级别、状态、党内职务、概述、来源、照片和标签。
- 任职经历包括开始/结束时间、机构、职务、地点、级别、说明和排序。
- 详情以人物卡片和履历时间轴展示。

### 3.3.1 时间线

- 提供独立时间线页面并支持页面权限配置。
- 横向最多选择 8 位人物，点击“更新时间线”后批量载入最新完整履历。
- 纵轴可选择“年”或“月”，点击更新后按所选粒度重新排布；各人物任职经历按起止时间对齐展示，并提示无法识别时间的记录。

### 3.4 关系图谱

支持从全部履历档案中选择任意两位人物，由已配置的大模型根据两人的基础信息与任职时间轴分析关系，展示关系类型、分析结论、履历依据和置信度，并可将分析结果保存到关系明细。支持列出和删除人物关系；禁止分析人物与自身的关系，人物删除时清理关联关系。

### 3.5 信息源

支持官方网站、本地文件夹和 FreshRSS。官方网站必须通过集中 WebFetch 服务获取，不得由业务代码直接抓取目标站点。支持连接检查、全量/增量同步、条目查看和状态显示。

### 3.6 智能分析

分析任务与分析结果合并为「智能分析」单页：任务区负责任务的创建、编辑、删除与全量/增量/自定义运行；结果区按任务筛选查看逐条与汇总结果。支持绑定多个信息源、调用可配置的 OpenAI 兼容接口；外部服务失败必须生成可诊断日志。

### 3.7 任务中心

统一展示采集与分析任务的待执行、运行中、成功、失败状态，以及开始时间、完成时间、摘要、错误和逐条日志。

### 3.8 权限管理

管理员查看用户列表并配置普通用户可访问页面。权限至少覆盖概览、履历档案、关系图谱、信息源、智能分析、任务中心和系统配置；权限管理仅管理员可见。历史数据中的旧键（分析任务、分析结果）在启动时自动合并为智能分析键。

### 3.9 系统配置

展示 `config/app.json` 及环境变量覆盖后的运行信息，API Key、密码、令牌、密钥等字段必须脱敏。

## 4. 非功能需求

- 后端采用 Python FastAPI，前端采用 Vue 3，数据库采用 SQLite。
- 页面适配桌面和移动端，中文显示清晰，核心操作有空状态与错误反馈。
- API 写操作具备参数校验；SQLite 启用外键约束。
- 时间统一保存为 UTC，界面/API 按北京时间显示。
- 日志按日切割，历史日志按保留天数清理，`logs` 不提交 Git。
- 环境相关地址、端口、路径和凭据必须来自配置或环境变量。
- 下载文件按 `data/年/月/日` 组织。

## 5. 部署与验收

- 支持 Windows PowerShell、Linux shell 和 systemd 启停。
- Jenkins 从主分支检出，执行后端测试和前端构建后增量部署；保留 `data`、`logs` 与本地环境配置。
- 健康检查 `GET /api/health` 返回 `{"status":"ok"}`。
- 验收必须包含后端全量测试、前端 TypeScript 检查与生产构建、启动冒烟和登录后核心 API 冒烟。
